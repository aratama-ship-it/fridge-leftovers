# 食材イラスト 拡張分の生成指示書

作成日: 2026-07-25
宛先: 画像生成の担当（Codex）

このアプリは「冷蔵庫の中に食材イラストが入っているUI」を固有の中心表現にしている。
イラストは装飾ではなく、在庫を思い出すための本体。文字の一覧を読ませず、見た瞬間に中身が分かることを狙う。
そのため**絵柄が既存48種とそろっていることが、単体の完成度より重要**。

## 0. 規模

「スーパーに基本的にあるものを網羅する」方針で、**108品目・9シート**を作る。

| | 数 |
|---|---|
| 今回描く品目 | **108**（うち5件は登録済みでイラストだけ無いもの、103件は新規） |
| シート数 | **9枚**（12品 × 9 = 108、端数なし） |
| 登録食材の増加 | 52 → **155** |
| イラストの総数 | 48 → **156** |

調味料20品目は方針の判断待ちのため別枠（→ 8節）。採用すれば +2シートで計11枚になる。

## 3. 絵柄の指示

水彩・不透明水彩ふうの食材イラスト。図鑑の挿絵に近い。

**守ること**

- 輪郭を黒線で囲まない。色と陰影で形を作る
- 被写体の外側に**ごく細い明るいクリーム色の縁**を付ける（棚の色に乗せても輪郭が読めるため）
- 光は左上からの柔らかい環境光。**地面に落ちる影は描かない**
- 彩度は自然でやや落ち着いた色。蛍光色・過度なツヤは使わない
- 角度は真横〜斜め45度。極端なパースを付けない
- 皿・まな板・小物・背景は描かない。器がないと成立しないものだけ器を描く
  （既存では、ごはんは青い縞の茶碗、ツナは白い小鉢）
- **文字・ラベル・パッケージ・ロゴは描かない**
- 1マス1食材。複数の食材を混ぜない

**避けること**

- 写真、3DCG、フラットなアイコン、ベタ塗り、線画
- 影を落として立体感を強調する表現
- 袋・缶・瓶などの容器（中身だけを描く）

## 4. 品目の選び方

次を見て決めた。**受け入率の統計ではなく、こちら側の判断**である点に注意。

1. 登録済みなのにイラストが無い5件（実データで確認）
2. **カテゴリーの偏り** — 拡張前は野菜19に対し、肉4・魚介5・果物2・乾物2と薄い。
   初回オンボーディングで「今夜の主役」を選ばせる設計にしたため、肉と魚介の薄さが直接効く
   （実データでも麺類・青魚は候補が1〜2件しかなかった）
3. 日本のスーパーの売り場（青果・精肉・鮮魚・日配・練り物・乾物・缶詰・漬物・冷凍・パン・粉）を一巡し、
   料理の材料になるものを拾った。菓子・酒・飲料・惣菜は対象外

抜けや不要があれば差し替える。

## 6. 納品の仕方

- PNG 9枚。ファイル名は各表の見出しのとおり（通し番号）
- **まずシート05だけ作って渡してほしい。** こちらでアプリへ組み込み、実機で大きさ・歪み・
  棚に並べたときの見え方を確認してから残り8枚に進みたい。9枚まとめて作ってから
  寸法や絵柄のずれが見つかると、やり直しが大きい
- 透過が保たれているか（背景が白く塗られていないか）を必ず確認する

## 7. 受け入れ基準

1. 1254 × 940 px、PNG、背景が透過
2. 12マスすべてに1品ずつ、マス中心に配置されている
3. 被写体がマス幅の60〜75%に収まり、隣のマスへはみ出していない
4. 既存シートと並べて、塗り・彩度・縁の処理・光の向きが揃って見える
5. 文字・ラベル・容器・皿・落ち影が入っていない（器が必要な数品を除く）

## 8. 調味料（方針の判断待ち・まだ描かない）

方針書は基本調味料をレシピの `pantry` に文字で持たせる設計で、在庫管理の対象にしていない。
一方で、ごま油はレシピの「あるとより良い」に単位「小さじ」で登場するのに在庫の単位一覧に
