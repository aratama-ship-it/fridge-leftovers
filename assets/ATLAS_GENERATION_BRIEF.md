# 食材イラスト 拡張分の生成指示書

作成日: 2026-07-25
宛先: 画像生成の担当（Codex）

このアプリは「冷蔵庫の中に食材イラストが入っているUI」を固有の中心表現にしている。
イラストは装飾ではなく、在庫を思い出すための本体。文字の一覧を読ませず、見た瞬間に中身が分かることを狙う。
そのため**絵柄が既存48種とそろっていることが、単体の完成度より重要**。

## 1. まず読むもの

- 技術仕様：[ATLAS_SPEC.md](ATLAS_SPEC.md)（寸法・マス座標・絵柄の条件）
- 参考にする既存シート：`ingredient-atlas.png` と `ingredient-atlas-expanded.png`
  **必ず開いて、隣に並べて見比べながら作る**

## 3. 絵柄の指示

水彩・不透明水彩ふうの食材イラスト。図鑑の挿絵に近い。

**守ること**

- 輪郭を黒線で囲まない。色と陰影で形を作る
- 被写体の外側に**ごく細い明るいクリーム色の縁**を付ける（棚の色に乗せても輪郭が読めるため）
- 光は左上からの柔らかい環境光。**地面に落ちる影は描かない**
- 彩度は自然でやや落ち着いた色。蛍光色・過度なツヤは使わない
- 角度は真横〜斜め45度。極端なパースを付けない
- 皿・まな板・小物・背景は描かない。器がないと成立しないものだけ器を描く
- **文字・ラベル・パッケージ・ロゴは描かない**（レシート由来の商品名は絵にしない）
- 単品、または少量をまとめた状態

**避けること**

- 写真、3DCG、フラットなアイコン、ベタ塗りのイラスト、線画
- 影を落として立体感を強調する表現
- 複数の食材を1マスに混ぜる（1マス1食材）

## 4. 作るシートと品目（3枚 = 36品目）

品目の選定は、次の3つを見て判断した。**受け入率の統計ではなく、こちらの判断**である点に注意。

1. **登録済みなのにイラストが無い5件**（実データで確認）
2. **カテゴリーの偏り**：現在は野菜19に対し、肉4・魚介5・果物2・乾物2と薄い。
   初回オンボーディングで「今夜の主役」を選ばせる設計にしたため、肉と魚介の薄さが直接効く
3. 日本の家庭料理でよく使うもの

## 5. 納品の仕方

- PNG 3枚。ファイル名は上の表のとおり
- 1枚ずつでよい。**まずシート5だけ作って渡してほしい**。
  こちらでアプリへ組み込み、実機で大きさと歪みを確認してから残り2枚に進みたい
- 透過が保たれているか（背景が白く塗られていないか）を確認する

## 6. 受け入れ基準

1. 1254 × 940 px、PNG、背景が透過
2. 12マスすべてに1品ずつ、マス中心に配置されている
3. 被写体がマス幅の60〜75%に収まり、隣のマスへはみ出していない
4. 既存シートと並べて、塗り・彩度・縁の処理・光の向きが揃って見える
5. 文字・ラベル・皿・落ち影が入っていない

## 7. 組み込み側で必要になる情報（画像担当は対応不要）

新規31品目は、イラストのほかに登録単位・保存場所・レシート認識パターン・栄養値が必要。
**初期単位はレシピの必要量と一致させる決まり**があるため（`scripts/check-initial-units.mjs` が検査する）、
レシピへ使う場合は単位を先に決める。この作業はアプリ側で行う。
