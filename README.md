# 冷蔵庫の残り物から今日の三択

冷蔵庫の在庫管理を中心に、残っている食材から今日作れる料理を3案に絞って提案するスマートフォン・iPad向けプロトタイプです。

## 試せること

- 作る直前の確認画面で、1〜4人分を選び、実際に使う材料と量を確認
- 「あるとより良い」食材は、調理前の確認画面で使う・使わないを選択
- レシピ画面の最上部にある食材イラストをタップし、冷蔵庫型の一覧から「今日使いたい食材」を再選択
- レシピごとの「最低限必要」と「あるとより良い」食材の区別
- 主食・肉・魚・卵・豆腐・野菜・麺・パン・汁物を含む定番・時短レシピ240件から、今ある食材に近い3件を提案
- 端末の月をもとに旬の目安となる食材を表示し、そうめんや鍋など季節に合う料理を候補内で少し優先
- ホーム右上の設定から、1人分のkcalとPFCバランスの概算表示を切り替え（初期はオフ）
- 手元にある追加食材の選択
- 食材の追加、編集、削除、残量の増減、保存場所による絞り込み
- 残量と買う数量は、直接入力・スライダー・プラス／マイナスボタンの3通りで変更
- 食材追加は「野菜・魚介・肉」などの分類からイラストをたどって選択し、最近追加した食材を各分類の先頭に表示（文字入力は一覧にない食材の補助）
- 食材追加画面の上部から、レシート撮影・画像選択による一括追加へ直接移動
- 一般的な食材323種類のイラスト表示（スーパーで買える範囲をほぼ網羅）
- レシート認識と文字入力は323種類に対応
- 冷蔵庫の絵で在庫を見渡し、同じタブの中で「一覧で直す」へ切り替えて残量を直す（下のタブは4つ）
- 常温保存の食材は、冷蔵庫の下にある二段のパントリー棚で確認・追加
- トップ画面では具体的な数量を出さず、食材イラストと「少なめ」で状態を確認
- 冷蔵庫・パントリーの食材を子どものイラストへドラッグして、食べて使い切った状態に更新
- 冷蔵庫の直下から「買うもの」「今日何作る？」「食材を追加」へ移動
- 料理提案は最初に3件を表示し、「あと3つ見る」で3件ずつ候補を追加
- 各料理の簡単な3手順を、必要なときだけ開いて確認
- 調理・使い切り・廃棄・在庫修正を月別の履歴へ記録し、最大1000件を直近50件から50件ずつ表示
- 調理履歴は使用食材と量をあとから修正でき、取り消して在庫へ戻すことも可能
- レシート写真を端末内OCRで読み取り、候補を確認して一括追加
- 「まだある」「先に使う」「使い切った」のワンタップ操作
- 使い切った食材の復元
- 調理後の在庫更新
- 次の買い物を売り場カテゴリと食材イラストから選択し、同じイラストの再タップで解除（文字入力は一覧にないものの補助）
- 現在の在庫とレシピの不足食材から「買うと料理につながるもの」を推薦
- 初回は主役の食材を1〜2品タップするだけで始められる（量は聞かない）
- 各棚の追加画面から「一覧から一度に追加する」を開き、10の売り場を順番に見て食材を足す
- 昨日つくった料理のあと、使った食材の残りを「ある／少ない／ない」で直す
- 食材登録時または在庫編集時に賞味期限を任意登録し、期限切れ・当日・3日以内をアプリ内で表示（端末通知は行わない）
- ブラウザ内への在庫・買い物データ保存と、設定からのファイル書き出し・読み込み（機種変更やバックアップ用）
- 設定から「共有をはじめる」でリンクを発行し、相手は登録なしで同じ冷蔵庫へ参加
- 招待リンクを開いた端末は確認画面を経て同じ冷蔵庫へ参加し、在庫・買い物・履歴・棚の状態を同期
- 共有中は保存操作のあと自動で同期し、上部の同期ボタンから手動でも更新可能
- ホーム画面に追加して全画面で起動し、通信が無くても開ける（アイコンの長押しから「レシピ」「買い物」「在庫」へ直接移動）

レシート認識には、アプリ内へ同梱したTesseract.jsと日本語学習データを使用します。写真を外部OCR APIへ送信せず、解析後の写真も保存しません。第三者ライセンスは[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)を参照してください。

現在は240件の定番・季節・時短料理を使う検証版です。時短料理は60件あり、いずれも調理時間の目安を15分以内にしています。栄養値は食品ごとの一般的な参考値と基本調味料の仮定から丸めた目安であり、商品表示や医療・栄養指導の代わりにはなりません。賞味期限は任意登録とアプリ内アラートに対応していますが、アカウントや端末通知には対応していません。複数端末間の同期は、限定リンクを知っている二人で使う簡易共有に限って対応しています。

## ホーム画面に追加する

スマートフォンのブラウザで https://aratama-ship-it.github.io/fridge-leftovers/ を開き、共有メニューから「ホーム画面に追加」を選ぶと、アドレスバーの無い全画面で開けます。一度開いたあとは、通信が無くても起動します。

- 起動に必要な画面・スクリプト・スタイルは先に取っておきます。食材イラスト（14MB）とレシート認識のTesseract（21MB）は初回が重くなるため、使ったものだけ後から溜めます
- 在庫データはこれまでどおりブラウザ内だけに保存されます。ホーム画面から開いても同じデータを見ます
- アイコンを長押しすると「レシピ」「買い物」「在庫」へ直接移動できます（Android。iOSは非対応）

アイコンは `node scripts/build-icons.mjs` が `assets/icons/` へ書き出します。素材は `assets/icon-src/` の2つ（冷蔵庫の絵だけを描いた透過PNGと、地の色）で、絵はアプリ内の食材イラストと同じ水彩です。**Androidは背景と前景を重ねて端末側が切り抜く**決まりなので、素材を分けたまま持ち、切り抜きのない用途（iOSのホーム画面・favicon）では絵を1.3倍で置いています。見え方は `assets/icon-preview.html` をブラウザで開くと、iOSの角丸とAndroidの丸マスクをかけた状態と実寸で確認できます。

更新の行き渡り方は `scripts/cache-version.mjs` が面倒を見ます。`index.html` の `?v=` と `styles.css` から参照する画像の `?v=` に加えて、`sw.js` の版と先読みリストも内容ハッシュから書き込むので、**`app.js`、`styles.css`、またはアトラスPNGを変えたら `node scripts/cache-version.mjs` を実行し、`index.html`・`styles.css`・`sw.js` を一緒にコミットします**（CIが `--check` で検出します）。

## 開発環境メモ

作業ツリーは iCloud Drive 上にありますが、`.git` は iCloud 同期による破損を避けるため `~/git-repos/fridge-leftovers` へ退避しています（`git init --separate-git-dir`）。リポジトリ直下の `.git` は、その場所を指す48バイトのテキストファイルです。

- 2026-07-25 に実施。それまでは iCloud が `.git` の競合コピーを14個作り、`refs/remotes/origin/main 2` のような不正な ref 名で `git fsck` がエラーを出す状態だった
- この構成は、この Mac 1台での作業を前提にしている。別の端末では `.git` の参照先が存在しないため git 操作ができない
